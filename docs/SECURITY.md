# Security notes

- NOVA resolves `cmd.exe` and `netsh.exe` using `GetSystemDirectoryW`, not the working directory or PATH. The terminal runs real Windows CMD commands with the current signed-in user's permissions. It is intentionally not sandboxed. Do not paste unknown commands.
- CMD uses a 30-second timeout; WLAN helper commands use 20 seconds. Each child is created suspended, assigned to a Windows Job Object configured with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, and only then resumed. This removes the pre-assignment execution window. Descendants inherit the job under normal Windows process creation; NOVA does not enable breakaway. If Windows refuses nested-job assignment, the command is not resumed. Timeouts terminate the job and closing the job handle is a final cleanup guarantee for processes still assigned to it. Output capture is capped at 1 MiB per stream while reader threads continue draining pipes. Terminal history is bounded to 1,500 lines and 4 MiB. Interactive stdin is not supported.
- Built-in Files is scoped to NOVA user data and rejects absolute paths, parent traversal, Windows-invalid/reserved names, and entries whose canonical target resolves outside the user-data root. Editor parent folders are created one component at a time and canonicalized after each step. This is defense-in-depth, not a security boundary against a hostile process running as the same Windows user.
- The editor accepts only relative paths under NOVA's user data, validates Windows filename rules, and limits files it opens/saves to 2 MiB.
- Wi-Fi profile deletion is allowed only for SSIDs recorded in NOVA's managed-profile manifest. If the manifest is corrupt or unreadable, deletion fails closed instead of assuming the profile list is empty.
- Wi-Fi credentials are never written into NOVA's own settings, app terminal history or logs. The `netsh` import method briefly writes the WLAN XML profile in the current user's TEMP directory. The file is created with a protected DACL granting access to its owner, SYSTEM and local Administrators; its writer is closed before `netsh` opens it, then NOVA deletes it immediately after import. If NOVA crashes, the orphan remains protected by that DACL and a later startup removes matching NOVA temp profiles older than 10 minutes. The XML remains plaintext while it exists, and local SYSTEM/Administrators are trusted.
- Windows may retain the imported WLAN profile after NOVA exits. This is managed by Windows and can be removed with the NOVA `password delete` command while in that SSID's setup mode.
- No admin elevation is requested.
- No auto-start registration, background service or autorun behavior is installed.


## 0.3.5 process and WLAN temporary-file protections

CMD and WLAN helper processes run outside the UI thread. The runner creates each child suspended, assigns it to a Windows Job Object configured with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, then resumes its initial thread. This removes the pre-assignment race. The shared process runner drains stdout and stderr continuously, retains at most 1 MiB per stream and enforces operation timeouts. A descendant that remains in the job is terminated when the job is explicitly terminated or its last handle closes. If the OS refuses assignment (for example, because of unsupported nested-job restrictions), the process is not resumed and the command fails closed.

The temporary WLAN XML is created with a protected DACL for the file owner, SYSTEM and local Administrators. NOVA closes its writer before invoking `netsh` to avoid share-mode conflicts, then deletes the file immediately after the import process exits. If NOVA crashes, the file remains protected by the DACL and a later startup removes matching files older than 10 minutes. The file content is still plaintext while it exists, and administrators/SYSTEM are intentionally trusted.
