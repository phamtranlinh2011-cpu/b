# Security notes

- The terminal runs real Windows CMD commands with the current signed-in user's permissions. It is intentionally not sandboxed. Do not paste unknown commands.
- Commands time out after 30 seconds and NOVA requests process-tree termination, then attempts to kill the command process directly as a fallback. After CMD exits, output readers get a 2-second drain window and one short post-termination grace period; NOVA detaches any reader that still has not closed instead of blocking the UI indefinitely. A descendant that retains inherited pipe handles may still outlive the command and leave a detached reader until the handle closes; robust Job Object supervision remains future work. Output is capped at 1 MiB per stream and truncation is reported. Interactive stdin is not supported.
- Built-in Files is scoped to NOVA user data and rejects absolute paths, parent traversal, Windows-invalid/reserved names, and entries whose canonical target resolves outside the user-data root. Editor parent folders are created one component at a time and canonicalized after each step. This is defense-in-depth, not a security boundary against a hostile process running as the same Windows user.
- The editor accepts only relative paths under NOVA's user data, validates Windows filename rules, and limits files it opens/saves to 2 MiB.
- Wi-Fi profile deletion is allowed only for SSIDs recorded in NOVA's managed-profile manifest. If the manifest is corrupt or unreadable, deletion fails closed instead of assuming the profile list is empty.
- Wi-Fi credentials are never written into NOVA's own settings, app terminal history or logs. The current `netsh` import method briefly writes the WLAN XML profile in the current user's TEMP directory; NOVA attempts deletion immediately after import and uses a scope guard on normal exit paths. It does not set a custom Windows DACL; abrupt termination or power loss can leave plaintext XML in TEMP. Replace this with direct WLAN API calls and secure memory handling before making a strong in-memory-only credential promise.
- Windows may retain the imported WLAN profile after NOVA exits. This is managed by Windows and can be removed with the NOVA `password delete` command while in that SSID's setup mode.
- No admin elevation is requested.
- No auto-start registration, background service or autorun behavior is installed.
